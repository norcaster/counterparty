# Changelog

The top numbered entry must match the release tag, `pyproject.toml` and `__init__.py`; the release workflow checks it.

## 0.1.0 — first public release

- Self-hosted Shared Record counterparty (draft protocol, in development): local root, signing and witness keys; key documents and root rotation; receiving and sending around MCP tool calls (receipts, notices, acknowledgements, missing-acknowledgement records); log witnessing; local records with retention; evidence export for `norcaster-verify`.
- `norcaster-counterparty sandbox`: a local log stand-in and a fictional hub for `QUICKSTART.md`. Not a SCITT transparency service.
- `norcaster_counterparty.mcp_server.add_shared_record` (extra `mcp`, MCP Python SDK `>=1.22.0,<3`): adds Shared Record to an existing MCP server (1.x low-level `Server` or `FastMCP`; 2.x low-level `Server` or `MCPServer`), including the notice tool.
- `norcaster_counterparty.openai_agents` (extra `openai-agents`, tested with `openai-agents` 0.24.0 and pinned to `>=0.24.0,<0.25`): your OpenAI Agents SDK agent sends a receipt on every call to a partner's MCP tool over Streamable HTTP and checks the partner's acknowledgement. `partner_server(...)` returns a configured `MCPServerStreamableHttp`. A tool input guardrail that does not allow a call registers a `blocked` receipt and sends a notice through the partner's notice tool; an optional `redact` hook commits to, and sends, the redacted call. The status (`acknowledged`, `mismatch`, `missing`, `invalid`, `refused`) goes on the tool output item's `custom_data`, on a `norcaster.shared_record` trace span, in `server.exchanges` and to `on_exchange`. Function tools and handoffs carry no MCP `_meta` and are not covered.
- `norcaster-counterparty proxy serve` (extra `mcp`): a local MCP proxy for agents whose SDK cannot set a request's `_meta`. It serves each partner's MCP server at `/mcp/<upstream>` on 127.0.0.1 behind a bearer token, signs a receipt for every tool call, forwards the call with it, checks the acknowledgement and removes it from the result. A control channel (`/control/v1`) takes the agent's own boundary decisions (`notices` for blocked calls, `decisions` for redacted ones) and lists statuses; missing acknowledgements are recorded on a schedule. Tools only. `/control/v1/tools/<upstream>` lists the partner's tool names; `/control/v1/health` reports the open sessions.
- `norcaster-counterparty proxy stdio --upstream NAME`: the proxy over stdio, started by the agent itself (no port, no token). `proxy hook --proxy proxy.json` (with the top-level `--config`) works with no proxy running: it records decisions and sends notices from `state_dir` directly.
- The proxy keeps sessions with the partners' servers open and shares them: one per upstream and exact set of outgoing headers, closed after `session_idle_seconds` (default 300; 0 turns pooling off), at most `max_sessions_per_upstream` (default 8). A call the partner's server answers with 404 ("Session terminated", not processed) goes once more on a new session; any other failure is reported `missing` and not sent again. On 127.0.0.1, 50 sequential calls took 18.6 ms each with pooled sessions and 28.7 ms with a new session per call (MCP SDK 2.3; 1.30: 18.7 and 42.0).
- Adapters for the local proxy:
  - `norcaster_counterparty.hooks.claude` (extra `claude-agent-sdk`, tested with 0.2.168, pinned `<0.3`): wraps your `PreToolUse` hooks for the proxied servers. A deny becomes a `blocked` receipt and a notice; changed arguments (`updatedInput`) become a `redacted` receipt, and the call is denied if the proxy cannot take that decision. `norcaster-counterparty proxy hook -- <command>` does the same for a Claude Code command hook and needs no extra. `norcaster_counterparty.hooks.ProxyControl` is the control channel's client.
  - `norcaster_counterparty.hooks.google_adk` (extra `google-adk`, Python 3.11 or later, tested with 2.12.0, pinned `<2.13`): `mcp_toolset()` reaches the partner through the proxy, and `before_tool_callback()` wraps your callbacks. A returned dict becomes a `blocked` receipt and a notice; `args` changed in place become a `redacted` receipt, refused if the proxy cannot take that decision. `status_callback` moves the proxy's status out of the result the model sees.
  - `norcaster_counterparty.hooks.langgraph` (extra `langgraph`, tested with langchain-mcp-adapters 0.3.2 and LangGraph 1.2; MCP SDK 1.x): `connections()` reaches the partner through the proxy, and `interceptors()` wraps your tool interceptors. One that answers without calling the next handler becomes a `blocked` receipt and a notice; one that passes the call on with other arguments becomes a `redacted` receipt, refused if the proxy cannot take that decision.
- Approvals and rejections are recorded as the Norcaster hub records them. A call a person approves is receipted `allowed` with rule `human_approval`; a call a person rejects is not sent, a `blocked` receipt with rule `human_rejected` is registered, and the partner gets a notice:
  - OpenAI Agents SDK: `require_approval`, and `await partner.reject(state, item)`.
  - Claude Agent SDK: the `hooks.claude.can_use_tool` wrapper. Claude Code: `proxy hook` on `PermissionRequest`, and on `PermissionDenied` with rule `claude.permission_denied`, needing no command.
  - Google ADK: `require_confirmation`.
  - LangGraph: `hooks.langgraph.approved()` and `@rule(HUMAN_REJECTED)`.

  The proxy's `decisions` take `outcome: "allowed"`, which yields to a pending redaction of the same call; a notice uses up any decision for its call. Decisions are kept in the `proxy_decisions` table.
- Several processes may share one `state_dir`. Every send to and receive from a partner takes a cross-process lock in `state_dir/locks/` (`flock`, `msvcrt` on Windows), so two processes never take the same sequence number or both acknowledge one receipt. SQLite waits up to 30 s for another process. `Counterparty(lock_timeout=60)`; a lock held longer refuses the call. Keep `state_dir` on a local disk.
- `examples/receive_one_call.py`, `examples/openai_agents_two_companies.py` and `examples/proxy_two_companies.py` (the proxy command with a LangGraph agent): two fictional companies, end to end against the local sandbox. QUICKSTART: "Any agent framework: the local proxy".
- Container image `ghcr.io/norcaster/counterparty` (UBI 9, uid 10001, about 330 MB), signed with the release key, with SBOM and provenance. It includes the local MCP proxy (`mcp==2.3.0` in the hash-pinned `docker/requirements.txt`) and exposes port 8790; the README shows a sidecar and a separate-container setup, with a TCP health probe. It includes the `mcp` extra, not the agent-SDK extras. The release scan (Trivy, fixable critical CVEs) found none with the proxy included, and the proxy's packages brought no high or critical findings.
- Before acknowledging, `receive` refuses (and signs nothing) a receipt whose `created_at` is more than `max_clock_skew_seconds` (default 300) from the receiver's clock, whose `ack_deadline` is before its `created_at`, whose sender's key document has expired, whose `sequence` is not one more than the last receipt accepted from that sender (the refusal names the receipts never accepted, which must be delivered first), or whose `previous_receipt` does not name that last receipt (a fork). A partner's key documents must map each key id to one public key and keep revocations, as the verifier requires; the sandbox's registration policy refuses such documents and statements under an expired key document.
- Needs `norcaster-verify[signatures]>=0.4.0` (key-id rules and the strict verifier); the base package depends on nothing else.
